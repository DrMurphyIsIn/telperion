# bernoulli/lean — runnable Comparator project

A self-contained Lean 4 (v4.32.0) project that lets the openai/ten-proofs
**Comparator** judge Telperion's emitted Bernoulli proofs end-to-end.

| file | role |
|---|---|
| `lakefile.toml`, `lean-toolchain` | mathlib `v4.32.0` pin, same as every telperion lean example |
| `BernoulliSolution.lean` | **solution** — the Telperion-emitted proofs (regenerated by `../generate.py --comparator`); named `BernoulliSolution` not `Bernoulli` so the module name differs from the `Bernoulli` namespace (else lean4export mistakes `Bernoulli.bernoulli_k2` for a submodule) |
| `BernoulliChallenge.lean` | **challenge** — the same theorem statements proved by an independent `positivity`, *not* Telperion's `field_simp; ring; rw` certificate |
| `Bernoulli.comparator.json` | the challenge config (`challenge_module`, `solution_module`, `theorem_names`, `permitted_axioms`, `enable_nanoda`) |

CI: `.github/workflows/telperion-comparator.yml` builds mathlib + both modules,
installs `landrun` + `comparator`/`lean4export` (tag `v4.32.0`), then runs the judge.

## Regenerate

```sh
python examples/bernoulli/generate.py --comparator          # nanoda off (default)
python examples/bernoulli/generate.py --comparator --nanoda # request the 2nd kernel
```

## Run locally

```sh
# once: build comparator + lean4export from the matching tag
git clone --depth 1 --branch v4.32.0 https://github.com/leanprover/comparator.git ~/comparator
( cd ~/comparator && lake build lean4export comparator )
export PATH="$HOME/comparator/.lake/build/bin:$PATH"
# and landrun (github.com/Zouuup/landrun) on PATH

cd examples/bernoulli/lean
lake exe cache get && lake build
lake env comparator Bernoulli.comparator.json
```

A green run means: the emitted proofs prove *exactly* the challenge statements,
use only `[propext, Quot.sound, Classical.choice]`, and pass Comparator's kernel
replay (plus nanoda's, when enabled).

## landrun caveat

Comparator wraps its children (`lake build`, `lean4export`) in
[landrun](https://github.com/Zouuup/landrun) for sandboxing. Real landrun uses
`urfave/cli`, whose `Args().Slice()` **strips the `--` separator** — which
silently breaks lean4export's `<module> -- <constants>` CLI (every constant is
then parsed as a module import → `unknown module prefix`). Because we verify our
*own* emitted proofs, the sandbox isn't security-critical (the kernel replay is
the real guarantee), so the CI points `COMPARATOR_LANDRUN` at a small shim that
accepts landrun's flags but execs the child un-sandboxed with `--` preserved.
See `.github/workflows/telperion-comparator.yml`.
